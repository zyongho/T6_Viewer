# MyTeslaViewer

테슬라 `TeslaCam` 영상을 로컬에서 복호화하고, 같은 녹화 시각의 최대 6개 카메라를 2행×3열 화면으로 동시에 확인하는 Windows용 Python 데스크톱 프로그램입니다.

## 제공 기능

- `RecentClips`, `SavedClips`, `SentryClips` 아래의 Tesla 기본 파일명 자동 인식
- 2행×3열 배치: 왼쪽 Pillar | 전방 | 오른쪽 Pillar, 왼쪽 Repeater | 후방 | 오른쪽 Repeater
- 카메라별 토글로 필요한 방향만 표시하고, 영상을 더블클릭하면 해당 방향을 크게 표시
- 목록 한 번 클릭 시 영상 영역에 썸네일(대표 화면 한 장), 목록 더블클릭·썸네일 클릭·재생 버튼 클릭 시 즉시 재생
- 재생이 끝나면 현재 필터 목록에서 **더 늦은 시각의 재생 가능한 장면**으로 자동 이동·재생(마지막 장면에서는 정지). 다음 장면의 카메라들은 재생 중에 한 채널씩 첫 프레임까지 미리 열어 두었다가 끝에서 바로 이어 재생합니다(전환 약 0.1~0.3초).
- 메모리 한도 4.5 GiB는 앱과 앱이 띄운 모든 하위 프로세스(분석 프로세스, ffmpeg, 지도 WebEngine)의 합계 기준입니다. 새 작업은 한도보다 여유를 두고만 시작하며, 한도에 가까워지면 분석 프로세스 → 짧은 ffmpeg 작업 → 다음 영상 미리 열기 순으로 해제하고, 그래도 부족하면 재생 속도만 낮춥니다. 재생 자체와 자동 다음 재생은 멈추지 않습니다. 운영체제의 강제 제한이 아닌 소프트 한도입니다.
- 고배속 제한: 2896×1876 원본을 여러 채널 동시에 고배속으로 디코딩하면 Qt 재생 파이프라인의 메모리가 수 초 만에 수 GB씩 늘어나므로 `채널 수 × 배속`을 상한(기본 24: 6채널 4×, 4채널 6×, 3채널 8×, 2채널 12×, 1채널 16×) 이하로 제한합니다. 각 영상의 처음·마지막 20% 구간은 최대 8×입니다. 상한과 객체 인식 프로세스 수(재생 중·고배속·정지 시)는 툴바의 `⚙ 설정`에서 바꿀 수 있고, 설정창에 예상 최대 메모리가 표시되며, 기본값과 추정치는 개발 테스트 PC(Intel i5-1340P 노트북, 내장 그래픽, RAM 16GB) 측정값 기준이므로 PC마다 적정값이 다를 수 있습니다.
- 객체 인식·GPS/차량상태 분석은 CPU 코어 수에 맞춘 여러 프로세스(정지 시 최대 12개, 재생 중 8개, 2× 초과 고배속 시 2개)에서 현재 영상 → 다음 영상 → 나머지 순으로 처리합니다. 스토리보드은 재생 중인 영상은 준비되는 칸부터 바로 표시하고, 나머지 모든 영상도 프로그램을 켜 두기만 하면 백그라운드에서 만듭니다(영상당 약 2초). 오른쪽 아래 상태 표시줄에 분석 프로세스 수·남은 작업·항목별 진행·메모리 사용량을 표시합니다. 6채널 중 한 채널만 크게 보고 시간을 옮긴 뒤 돌아와도 모든 채널이 그 시각으로 맞춰지며, 재생 중 0.4초 이상 어긋난 채널은 자동으로 다시 맞춥니다.
- 각 영상 아래에 단일 화면 20구간·여러 화면 10스토리보드(대표 장면)를 표시하고 클릭하면 6채널 공통 타임라인에서 해당 시각부터 재생
- 영상 영역 아래의 재생바(원하는 위치를 클릭하거나 재생점을 드래그해 이동)와 재생 버튼 바로 옆의 1×·2×·4×·8×·16×·가변 속도 버튼
- 실제 재생으로 지나간 고유 구간이 영상 길이의 75%를 넘으면 목록 글자색을 변경. 타임라인 건너뛰기는 시청 구간으로 세지 않습니다.
- 목록 열: `일시`(날짜·요일·시각), `복호`(🔓 복호됨 · 🔒 암호화), `폴더`(최근·저장·감시), `주행`(SEI 속도·기어 기준 주행/정지, 정보가 없으면 `-`), `Event`(복호화된 event.json 정보가 있으면 Yes), `분석`(객체 인식·스토리보드·SEI 진행률을 원형 아이콘으로, 마우스를 올리면 항목별 개수). **열 제목을 누르면 필터 창**이 열립니다: 일시는 날짜 범위·시간 범위(자정을 넘는 범위 가능)·요일, 나머지는 엑셀처럼 체크박스.
- `가변` 버튼: 선택한 검출 대상의 움직임이 없으면 최대 16×, 움직임 또는 알려진 이벤트 시각 근처에서는 선택한 수동 속도. 카메라 자체가 이동 중인 영상은 오탐 방지를 위해 기본 속도로 재생
- `⚙ 설정`의 `객체 인식` 아래 `인식 대상(비주행 영상)`에서 🚶 사람·🚗 자동차(버스/트럭 포함)·🏍 오토바이·🚲 자전거/PM을 선택. 모델 분석 결과를 클래스별로 캐시하므로 선택을 바꿔도 영상을 재분석하지 않음. **실제로 움직인 대상만** 셉니다: 추적한 물체가 처음 보인 위치에서 자기 크기의 1/4 이상 이동해야 하며, 주차된 차량·가끔만 검출되는 물체·같은 차의 중복 검출은 제외합니다. 카메라 제목의 신호등 뒤에 움직인 대상 아이콘을 표시하고, 스토리보드 아래와 재생바의 주황색 막대가 움직임이 있던 구간입니다.
- `⏭ 스킵`: 선택한 대상이 움직인 다음 장면 1초 전으로 이동하고, 현재 영상에 더 없으면 변화가 있는 다음 장면으로 넘어갑니다(분석된 조용한 장면은 건너뜀). `⏩ 자동 스킵`를 켜면 재생 중 움직임이 없는 구간을 자동으로 건너뛰어 다음 움직임 1초 전으로 이동합니다. 분석된 카메라 기준으로 동작하며, 아직 분석되지 않은 영상과 주행 중 영상(판정 불가)은 그대로 재생합니다.
- `⚙ 설정` → 분석: `백그라운드 분석 허용`을 켜면 체크한 항목(객체 인식·스토리보드·SEI 주행 정보·썸네일)을 모든 영상에 대해 미리 처리하고(보고 있는 영상 먼저), 끄면 보고 있는 영상만 처리합니다. 항목을 모두 끄면 분석 없이 재생만 합니다.
- 지도에서 경로나 점을 클릭하면 해당 장면의 가까운 시각부터 재생; 현재 영상 경로는 빨간색, 다른 영상 경로는 파란색, 현재 위치는 차량 진행 방향을 가리키는 주황색 화살표로 표시. 목록에서 장면을 선택하면 지도도 해당 위치로 이동하고, 위치 정보가 없는 영상(주차 중 녹화 등)이면 시작 화면으로 되돌려 이전 위치와 혼동하지 않게 합니다.
- 화면은 탐색(목록) | 영상 | 지도 세 부분으로 나뉩니다. 영상 위 카메라 줄 양 끝의 `◀`·`▶` 버튼(창 경계에 붙어 있음)이나 경계 막대를 끌어 목록·지도를 숨기고 다시 열 수 있습니다.
- `암호화 영상 복호화` 버튼은 복호화할 영상이 있는 폴더에서만 보이고, 이미 복호화된 폴더를 열면 숨겨집니다.
- `⚙ 설정`에서 `객체 인식`을 끄면 카메라 제목에는 카메라 이름만 표시하고 신호등·아이콘·주황색 변화 표시를 모두 숨깁니다.
- 설정 옆 `ⓘ 정보`에서 버전·버전 기록(`docs/CHANGELOG.md`)·오픈소스 고지·라이선스 전문(`licenses` 폴더)을, 설정의 `❓ 도움말`에서 기능과 사용법(`docs/help.html`)을 볼 수 있습니다. 설정의 `모든 설정·기록 삭제`는 `%LOCALAPPDATA%\MyTeslaViewer` 폴더(필요하면 영상 폴더의 분석 결과까지)를 지우고 종료합니다.
- 비정상 종료 시 원인 파악을 위해 `%LOCALAPPDATA%\MyTeslaViewer\crash.log`에 Qt 경고·Python 오류·네이티브 크래시 스택·메모리 해제 기록을 남깁니다.
- 같은 시각의 카메라 자동 묶음, 재생·일시정지·공통 탐색바·±5초 이동
- 일반 MP4는 바로 재생
- Tesla 2026.20+ 암호화 클립은 Tesla 계정의 Bearer 토큰으로 파일별 키를 요청한 뒤 PC에서 로컬 복호화
- 복호화된 파일은 별도 `TeslaCam_Decryped` 폴더에 저장(기존 `TeslaCam_Decrypted` 폴더가 있으면 재사용)
- 복호화 성공과 정상 MP4 출력 검증이 끝난 원본 암호화 `.mp4`만 선택적으로 삭제
- `event.json`/`events.json`은 영상 복호화 키로 복호화되지 않으므로 복호화 대상에서 제외합니다. 차량에서 암호화하지 않은 event.json만 그대로 복사해 이벤트 정보(`Event` 열·지도 위치)로 사용합니다.
- 토큰은 저장하지 않으며 영상 바이트는 Tesla 서버로 업로드하지 않음

## 실행

```powershell
py -3.10 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python run.py
```

`📂 TeslaCam 열기`에서 USB 드라이브 또는 `TeslaCam` 폴더를 선택하면 됩니다. 폴더를 창으로 끌어 놓아도 됩니다.

썸네일·20구간 스토리보드·객체 인식 결과·SEI 파싱 결과는 각 MP4가 있는 폴더의 `.myteslaviewer_cache`에 저장합니다. 원본 크기 또는 수정 시각이 바뀌면 해당 결과를 다시 만듭니다. 저장 권한이 없어도 재생은 가능하지만 다음 실행 때 재분석합니다. 영상 디코딩은 프로그램에 포함된 FFmpeg 라이브러리(PyAV, LGPL 빌드)를 쓰므로 ffmpeg를 따로 설치할 필요가 없습니다. 설정·시청 기록·움직임 분석 목록·크래시 로그는 `%LOCALAPPDATA%\MyTeslaViewer` 폴더에 저장합니다(이전 버전이 실행 폴더에 만든 파일은 처음 실행 때 옮겨 옵니다). 캐시가 있으면 이를 우선 읽으며, 검출 대상 선택을 바꿀 때는 저장된 클래스별 결과를 다시 집계합니다.

## 암호화 영상 복호화

암호화 영상은 파일 확장자만 `.mp4`이고 일반 MP4 헤더가 없으므로 먼저 앱의 `암호화 영상 복호화`를 선택합니다. `dashcam.tesla.com`에 로그인한 뒤 개발자 도구 Network에서 요청의 `Authorization: Bearer ...` 값을 복사해 입력합니다. 토큰이 만료되면 새 토큰을 입력해야 합니다.

복호화가 끝나면 앱이 자동으로 출력 폴더를 다시 열어 목록을 갱신합니다. 목록에서 재생할 장면을 선택하세요. Tesla 계정 권한이 없는 타인 차량의 파일은 복호화할 수 없습니다.

복호화 창의 삭제 옵션은 기본 선택되어 있습니다. 확인된 정상 MP4가 출력된 경우에만 원본 암호화 `.mp4`를 삭제하며, 삭제 전 최종 확인을 표시합니다. 삭제하지 않으려면 확인란을 해제하세요. `event.json`/`events.json` 등 부가 파일은 삭제하지 않습니다.

`TeslaCam_Decrypted` 폴더를 열면 안에 남아 있는 암호화 `event.json`/`events.json` 및 MP4를 형제 폴더 `TeslaCam_Decrypted_EncryptedBackup`으로 옮깁니다. 기존 파일을 영구 삭제하거나 복호화된 파일을 덮어쓰지 않습니다. 그 폴더에 아직 복호화되지 않은 MP4가 있으면 `암호화 영상 복호화` 버튼으로 복호화해 출력 폴더에 넣을 수 있습니다(event.json은 대상 아님). 키를 반환받지 못한 파일은 복구용 폴더에 그대로 남으며, 이미 복호화된 MP4는 다시 처리하지 않습니다. 복호화할 영상이 없는 폴더에서는 이 버튼이 비활성화됩니다.

암호화된 `event.json`은 MP4와 달리 Tesla 키 요청에 필요한 소유권 메타데이터가 없어 영상 복호화 키로 풀 수 없습니다. 그래서 복호화 대상에서 제외하며, 복호화 로그에도 event.json 관련 오류를 남기지 않습니다. 암호화된 event.json은 원본 위치에 그대로 둡니다.

신호등은 [OpenCV Zoo YOLOX-s INT8](https://github.com/opencv/opencv_zoo/tree/main/models/object_detection_yolox) 모델이 인식한 대상의 프레임 간 이동을 기준으로 계산합니다. 모델 파일은 `models/yolox_s_int8.onnx`에 있으며 영상을 외부로 전송하지 않습니다. 처음 로딩 시 분석은 최근 항목부터 역순으로 진행하고, 항목을 선택하면 선택 항목 → 그보다 이른 3개 항목(시간순) → 나머지 최근순으로 진행합니다. 나뭇잎·현수막은 검출 대상에서 제외하지만 오인식은 가능하며, 작은 물체·잠깐 나타난 물체·킥보드와 카트(별도 학습 클래스 없음)는 놓칠 수 있습니다. 카메라가 움직이는 영상은 배경 이동과 실제 물체 이동을 신뢰성 있게 분리하지 못해 `판정 불가`로 표시합니다. 신호등의 `변화 없음`은 안전을 보증하지 않으므로 사고 장면의 최종 확인에는 1× 속도를 사용하세요. 6개 고해상도 카메라를 동시에 16×로 디코딩할 때는 PC 성능에 따라 끊김이 생길 수 있으므로 필요한 카메라만 선택하면 부담을 줄일 수 있습니다.
